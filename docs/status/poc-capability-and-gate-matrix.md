# POC capability and gate-status matrix

Status snapshot: 2026-08-14, PR #38 (`sweep/round-4-adversarial`, head `116a84d`): all three CI workflows green on the PR; the authoritative CI-built OCI subject bundle is retained; `master` has not been updated since the round-4 sweep began.

This matrix records the current status of every `AC-POC-*` acceptance criterion
(binding design Section 0.6 and implementation plan Section 8.3) and of the
`PG-00` through `PG-04` gates. It is a documentation artifact, not evidence: a
status moves to "evidenced" only when a retained record with exact subject,
procedure, measurements, and artifact hashes exists (see
[Testing and evidence contract](../testing/evidence-and-validation.md)).

Classification terms:

- **Implemented and evidenced:** code exists and a retained record documents the result.
- **Partially implemented / partially evidenced:** core behavior exists, but a mandated part is missing or its evidence is not retained.
- **Designed/planned only:** documented contract or operator procedure; no execution.
- **Deferred / blocked on authorization:** deliberately postponed, or requires user authorization (for example any Azure write).

Record naming: each record binds the commit that produced it and is re-settled by `pnpm run verify`; the active lane set is `*-116a84d608f3.json` (lanes) and `oci-digest-bundle-e456dd0cd791.json` (CI-built subject, PR #38 merge ref); older records are archived under `docs/evidence/archived/`.

## Updating this matrix

Reclassify a row only with retained evidence (a gate manifest, an executed
command's retained record with artifact hashes, or a user-authorized decision).
Documentation wording does not change a status; evidence does. When a status
changes, update this file, the documentation index, and the affected gate's
section in the implementation plan together.
